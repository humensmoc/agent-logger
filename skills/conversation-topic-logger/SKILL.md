# 对话日志

此 Skill 记录 Agent 被触发后的用户回合。安装和启用是两回事：把 Skill 放入用户目录仅提供能力；项目中的 `AGENTS.override.md`、`CLAUDE.local.md` 或 Cursor 规则才要求每轮运行。无会话时不会自行生成日志。

## 首次启用或换设备

给用户说明默认记录内容，并逐项询问是否排除。默认保留用户消息原文，包括粘贴的代码、链接和文本；附件用占位符，图片可附简短客观说明。其他默认字段为回复摘要、设备、项目、来源绝对路径、时区、文件改动、所用 Skill、AI 名称及模型。日期、时间和日内回合号是日志结构，无法关闭。可排除字段名见下表。

| 字段 | 含义 |
|---|---|
| `user` | 用户输入原文 |
| `image_description` | 图片说明 |
| `reply` | AI 回复摘要 |
| `device` | 设备名 |
| `project` | 项目名 |
| `source` | 来源工作区或仓库绝对路径 |
| `timezone` | 时区 |
| `files` | 本轮文件改动 |
| `skills` | 本轮使用的 Skill |
| `ai` | Agent 产品名称 |
| `model` | 模型 ID |

1. 问用户日志根目录的绝对路径。建议放在公开仓库外；若放在仓库内，单独询问是否要在本地 Git exclude 中忽略。不得自行改用别的目录。新设备没有本机配置时重新询问。
2. 向用户展示上表，问有没有不想记录的字段。不要只根据个人判断关闭原文；按用户回答传给 `--exclude-fields`。
3. 单独询问用户是否要把 Skill 文件、`AGENTS.override.md`、`CLAUDE.local.md` 和 Cursor 规则留在本地。规则的 `local` 模式将这些路径写入该仓库的 `.git/info/exclude`；`shared` 模式允许主动提交和团队共享。日志目录在目标仓库内时，另用日志的 `local` 或 `shared` 选择控制是否忽略。说明 `.git/info/exclude` 不影响已跟踪文件或其他克隆。不要替用户默认选择。
4. 用户提供或确认现有目录后，从实际 Skill 目录运行 `python scripts/logger_setup.py configure --path <绝对路径> --exclude-fields <字段列表>`。Mac 可用 `python3`。只有用户明确要求创建目录时才加 `--create`。然后运行 `install --repo <目标仓库路径> --visibility local|shared --log-visibility local|shared`，最后运行 `resolve` 并检查输出。
5. 若 `CONVERSATION_LOG_ROOT` 环境变量存在，它优先于本机配置。无效时要求用户修正或清除，不能回退到别的路径。

安装脚本仅保存当前设备的配置，不会移动旧日志。当前仓库已跟踪日志、生成的规则，或受 Git 跟踪的 `AGENTS.md` 已含日志约束，而用户选择 `local` 时，脚本拒绝宣称它们已被隐藏；需由用户决定如何处理 Git 索引和公开历史。Codex 在同目录优先读取 `AGENTS.override.md`，Cursor 使用本地规则。`.git/info/exclude` 只忽略未跟踪文件。

## 每轮执行

在发送最终回复前，读取本文件并从**实际读取的 Skill 所在目录**运行 `scripts/logger_setup.py resolve`。输出的 `log_root` 已验证为存在且可写，`excluded_fields` 决定本轮哪些字段不写。若目录缺失或失效，向用户报告当前设备名、候选路径和具体错误，询问这台设备要使用的日志路径；本轮仍无法写入时，在最终回复中明确说明未记入日志及原因，不无限重试。选中的路径无效时不擅自回退到其他路径。

1. 取当前本地日期时间 `YYYY-MM-DD HH:mm:ss` 及本地时区。Windows 用 `socket.gethostname()`；macOS 优先 `scutil --get LocalHostName`，失败后用 `socket.gethostname()`。设备名获取失败时写 `未知设备`。
2. 用 `git rev-parse --show-toplevel` 取得来源仓库；非仓库使用当前工作区。来源项目与日志目录、Skill 安装目录分开。项目名取来源仓库或工作区最后一级，供阅读；将规范化的来源绝对路径写入 `source` 作为项目标识，避免不同目录的同名项目混淆。不同设备上的路径默认是不同来源，不猜测它们是同一项目。同日日文件的回合号在所有项目间全局递增。
3. 只记录当前用户实际输入，不记录系统提醒、IDE 自动上下文或 hook 注入文本。启用 `user` 时按下文「用户原文规则」逐字保存。启用 `image_description` 时按图片规则补充说明。
4. 回复字段用 1 至 2 句概括实际完成的工作。文件字段只列本轮真实改动，不列日志自身的例行追加。Skill 字段只列本轮实际使用的 Skill。
5. 启用 `ai` 或 `model` 时按下文「环境字段」确定；不能拿默认配置或其他会话的记录猜测模型。
6. 将未排除的字段追加到 `<log_root>/YYYY/MM/YYYY-MM-DD.md`。当天文件不存在时先写 `# YYYY-MM-DD 每日记录`。只追加，不回写旧回合。
7. 重新读取日文件，验证本轮存在、回合号唯一、Markdown 结构完整。成功后再发送最终回复。

## 记录格式

未排除字段时使用下面的格式；被排除的字段整项省略。标题中 `device` 或 `project` 被排除时也直接省略对应段，不写占位值。

```markdown
### 回合 N | HH:mm | 设备名 | 项目名
- **来源**：`/example/project` | 时区=Asia/Shanghai
- **用户**：
  > 用户第一行
  > 用户第二行
- **图片说明**：图 1：可见内容。
- **回复**：本轮实际完成事项。
- **文件**：
  - 修改 `path/to/file`：改动概要
- **Skill**：conversation-topic-logger
- **环境**：AI=Codex | 模型=未知模型
---
```

若只排除了 `source` 或 `timezone` 之一，来源行只保留另一项；两者都排除则省略整行。`ai` 和 `model` 同理。文件路径相对来源项目；项目外路径用绝对路径。

## 用户原文规则

启用 `user` 时，用户输入必须完整保留，不概括、不删减、不润色；错别字、口语、标点和中英混写都照原样写。只有 `reply` 字段做概括。

- 每一行原文前加 `  > `（两个空格缩进与引用符）；空行写 `  >`，保留原有换行和段落。
- 粘贴的长文本、代码、日志、链接同样全文照录；代码块围栏也放在引用行内，保持原样。用户通过斜杠命令调用 Skill 时，记录实际输入的命令及参数原文。
- 图片、文件附件等无法以文本记录的内容，在对应位置写 `[图片]`、`[附件：文件名]`。不把客户端或 hook 自动注入的提醒、环境信息当成用户原文。
- 若启用 `image_description` 且本轮含图片，在用户引用块之后、`reply` 之前另写 `**图片说明**`。按出现顺序标“图 1”“图 2”等，每张用 1 至 2 句客观描述可见内容，必要时摘录确实清晰可辨的关键文字或数值。说明只作补充，不替代原文中的 `[图片]` 占位符。
- 只根据实际可见内容描述，不从提问、回复或文件名反推。图片无法读取或内容无法辨认时写“图 N：图片内容无法辨认”。无图片时省略整个 `图片说明` 字段。若排除了 `user` 但保留 `image_description`，仍按本项记录可见图片，不补记被排除的用户文字。

## 环境字段

启用 `ai` 时，按实际会话环境写 `Codex`、`DSH（DeepSeek Harness）` 或 `Claude Code`；存在 `$DSH_WEB_URL` / `$DSH_SESSION_ID` 时写 DSH。其他环境无法确定时写 `未知 AI`。启用 `model` 时只使用当前会话运行记录里的完整模型 ID；无法可靠定位时写 `未知模型`，不能将默认模型配置当作实际模型。

- **Codex**：从当前会话 JSONL 最后一条 `turn_context.payload.model` 取值。会话 ID 优先使用 `$CODEX_SESSION_ID`，其次 `$CODEX_THREAD_ID`；只能读取与当前 ID 匹配的 JSONL，禁止直接取 `~/.codex/sessions/` 下的“最新文件”。
- **DSH**：从 `$DSH_SESSION_JSONL` 检索 `"model":"..."` 并取出现次数最多的值；`.zstd` 文件先用 `zstdcat` 解压到标准输出。失败写 `未知模型`。
- **Claude Code**：从当前活动 transcript 最后一条 `type="assistant"` 记录的 `message.model` 取值。优先使用 hook 输入中的 `transcript_path`；并行会话无法唯一定位时不得猜测。

若用户排除了 `ai` 或 `model`，不读取对应会话记录，也不写对应字段。

## 串行写入与边界

- 在日志根目录打开 `.conversation-topic-logger.lock`，使用 `OpenOrCreate`、`ReadWrite` 和 `FileShare.None`。持有句柄时重读日文件、计算下一个回合号、追加并回读验证，最后在 `finally` 中释放句柄。锁占用最多短暂重试 3 次；访问拒绝立即报告。锁文件可保留。
- 同一日志目录的所有写入者须遵循这一锁协议。云同步设备间没有可靠的共享锁，可能产生冲突。
- 配置路径不会赋予文件系统权限；遇到权限或沙箱阻止时说明实际路径与错误，不擅自改目录或放宽权限。
- 即使日志目录存在，也要按当前会话的实际权限验证。受限环境可能需要用户将日志目录加入允许写入范围；Skill 不能自行扩大沙箱权限。若当前环境支持审批，遵循该机制。路径或权限问题只阻止日志步骤，不能无限重试或阻止原任务回复。
- 低价值对话仍按回合记录，但不额外生成主题摘要。对历史文件只追加当前新回合，不回溯、改写或补造旧对话。
- 不创建没有 AI 会话的日期日志，也不运行 Git 活动统计。需要定时生成或 Git 日结时应另行配置流程。
